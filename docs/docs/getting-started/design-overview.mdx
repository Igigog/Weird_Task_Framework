# Design overview

Weird Task Framework was born out of a procedural quest pack, and this procedurality is imprinted in its DNA. WTF is built around reusable components, dynamically provided values, composability and customization. The core question WTF tries to answer is:

> How do you retain expressiveness while building quests from small, composable pieces?

The answer, it turns out, is complicated. There are stupidly many inter-interacting parts in a quest: *setup*, *logic*, *success and failure conditions*, *rewards*, *description*, *dialogues*, etc. All of these parts may interact with each other; for example, *description* needs to show *rewards*, which depend on *logic* of the quest and initial conditions in *setup*. In short, it is a pain to get them all moving.

WTF employs a row of tricks to reduce complexity of this self-suffocating mess. Let's look at an example:

```json title="sid_bribery.json"
{
...
    "entities": [
    {
        "section_name":"drx_sl_quest_item_2",
        "id": "init$ igi_helper.give_to_actor(|this.section_name|)",
        "release": "on_finish$ alife_release_id(|this.id|) or 1",
        "link_id": "package"
    },

    {
        "id": "init$ alife_create('script_zone', |this.pos|, |this.lvid|, |this.gvid|).id",
        "release": "del$ alife_release_id(|this.id|) or 1",
		
        "pos": "@$ vector():set(-100, -30, -397)",
        "gvid": 449,
        "lvid": 162028,
        "link_id": "zone"
    },

    {
        "CONTROLLER":"@$ wtf_target_deliver.Deliver",
        "id": "init$ |package.id|",
        "where": "init$ |zone.id|"
    }
    ],
    ...
}
```

### Inline Lua

Inline lua is used heavily in WTF. You can express a lot in a single line of lua; you can express much more in six. This makes the state very explicit - you can read what happens in the whole quest in these poor 6 lines of lua. 

### Independent Entities

Quests in WTF are built around entities - blobs of data with optional logic glued on top. In this quest there are 3 entities, but only one of them has a controller, meaning only one has any logic to run. Regardless of amount, once the logic starts running, controller can only access its own entity - other ones are completely inaccessible to it.

### Macros and Linking

Inline lua runs using a macro system. These things with `$` before inline lua define when, and how, the code will be run. Links allow the results of macros to be interconnected; macro system is the only thing that can move values between entities.

### Controllers

Single lines of inline lua can't run your quest - trust me, I tried. Controllers are written in actual `.script` files and take care of the whole subtask lifecycle - they define success and failure conditions, run status functor and have their own initialization and shutdown logic.

### More Macros

```json title="heavy.json"
    ...
    "description": {
        "locations": ["$ igi_description.get_smart_name_by_id(|frame.smart_id|)"],
        "factions": ["$ |frame.faction|"]
    },
    "rewards": {
        "money": "@$ 2000 + 400 * |frame.squad_size|",
        "goodwill": "@$ 20 + 4 * |frame.squad_size|"
    },
```

Once you get a hammer, you build a framework around it. Entities are not the only thing enjoying benefits of procedural generation - all the systems of WTF are built around macros, inline lua and controllers. Once you grasp these, you're all set.
